# Using it without WiFi (outdoors / offline)

**English** · [简体中文](OFFLINE.md)

In places without a home router, such as outdoors, at exhibitions or in basements, neither of the duck's two control paths needs the internet:

- **Phone voice**: the duck opens its own 2.4 GHz hotspot, the phone connects to it and sends recordings to the duck, where they are recognized by the on-board Vosk. No internet needed.
- **Physical gamepad**: connects directly to the duck's board over Bluetooth, fully local, unrelated to WiFi.

The two paths are independent of each other and can be used at the same time. They are described separately below.

---

## 1. Phone voice (duck opens a hotspot)

The phone microphone is only given to the browser in a **secure context** (HTTPS), so the address for this path is `https://10.42.0.1:8000/m`. The certificates are generated by the duck itself on first boot (a local CA + server certificate), located at:

```
/etc/microduck/tls/ca.crt        # Certificate for the phone to trust (can be downloaded)
/etc/microduck/tls/duck.crt      # The duck's own HTTPS certificate
/etc/microduck/tls/duck.key      # Private key, used only by the board itself
```

### First-time preparation

1. **Set a web console login password first**. The hotspot password `microduck` is a public default, so anyone on the same hotspot can open Studio.
   Set it in Studio under “更多 → 登录密码” (More → Login password); do not demo in public without a password.
2. Connect the phone to the duck's hotspot:
   - Find `Microduck-xxxx` in the WiFi list (xxxx is the duck's 4-character name), password `microduck`;
   - When the phone says "This network has no internet access", choose **Stay connected**, and temporarily **turn off mobile data** (some Android phones bypass WiFi networks without internet).
3. Open **https://10.42.0.1:8000/m** in the phone browser.
   - The first time it will warn that the certificate is not trusted; this is normal: continue with step 4.
4. **Download and trust the duck's own CA**:
   - Under “更多 → 手机麦克风证书” (More → Phone microphone certificate), tap “下载证书” (Download certificate) to get `Microduck-Local-CA.crt`.
   - Only trust a CA downloaded from your own duck's hotspot or a trusted connection. If in doubt, run `openssl x509 -in /etc/microduck/tls/ca.crt -noout -fingerprint -sha256` on the duck and compare the SHA-256 fingerprint with the downloaded certificate.
   - **iPhone**: tap download → Settings → Profile Downloaded → Install;
     then go to Settings → General → About → **Certificate Trust Settings** and turn on `Microduck Local CA`.
   - **Android**: Settings → Security → Encryption & credentials → Install a certificate → **CA certificate**, and choose the file you just downloaded.
   - After installing, refresh this page.
5. Go back to “更多 → 语音方式” (More → Voice mode), choose “自动” (Auto) or “手机麦克风” (Phone microphone), and hold “手机说话” (Phone voice) to control the little duck.

If you switch to another phone later, you need to install the CA again; the on-board microphone and the physical gamepad do not need a certificate.

> If you already have a duck but its certificate is old (only a single self-signed leaf, no `ca.crt`), run
> `sudo microduck-firstboot --tls-only` on the board to regenerate it; the old certificate is automatically backed up as `*.bak-<timestamp>`,
> then run `sudo systemctl restart microduck-studio`. When Studio finds `duck.crt` / `duck.key`, it automatically starts with HTTPS.
> Devices that have not enabled HTTPS yet can still open the web console at the original HTTP address. The phone microphone requires the certificate to be generated and trusted first.

### Going back from the hotspot to home WiFi

On the phone, in the “更多 → 户外” (More → Outdoor) card, tap “关热点，回家里 WiFi” (Turn off hotspot, back to home WiFi). The phone will disconnect; this is normal:

- After the duck turns off the hotspot, NetworkManager automatically reconnects to the home WiFi using the saved configuration.
- After the phone reconnects to the same WiFi, open `https://duck-xxxx.local:8000/m` or `https://duck-xxxx:8000/m`. The factory certificate covers these two hostnames and the fixed hotspot address.
- Devices that have not enabled HTTPS yet continue to use `http://duck-xxxx.local:8000/` or `http://duck-xxxx:8000/`.

If the duck does not reconnect to the home WiFi, the hotspot usually comes back by itself (immediately to about 2 minutes); reconnect to `Microduck-xxxx` and read the reason in red on the card.

## 2. Physical gamepad (Bluetooth)

The physical gamepad goes through neither WiFi nor Studio:

1. Pair it by following the wizard on Studio's gamepad page, or use the official tool on the board: `robotctl pad pair`.
2. After pairing, run `bluetoothctl trust <gamepad address>`; it will then reconnect automatically on boot.
3. The gamepad's buttons are read by `padd` from `/dev/input/event*` and then go through `/run/robotd.sock`, entirely on the board.

Without home WiFi you don't need to change anything; a paired gamepad reconnects on boot as usual.

The virtual gamepad on the phone is a different path: it goes through WiFi / Studio and needs the phone and the duck on the same network (either the hotspot or home WiFi works).

## 3. Troubleshooting

- **The browser says the certificate is not trusted**: the CA has not been installed yet, or the page was not refreshed after installing. Reinstall following step 4 above; on iPhone remember to also turn it on in "Certificate Trust Settings".
- **The “手机说话” (Phone voice) button is grayed out / no microphone access**: make sure the address is `https://`, not `http://`; make sure the CA is trusted; on iOS you need to allow the microphone in the pop-up.
- **The phone keeps using cellular and cannot open the duck's page**: turn off mobile data, or in that WiFi network's details choose "Stay connected" / turn off "Switch networks automatically".
- **Turning the hotspot on/off is slow / the phone cannot reconnect after dropping**: bringing the hotspot up or down takes from a few seconds to tens of seconds; wait 10 seconds before looking for `Microduck-xxxx`. When switching back to home WiFi the duck also needs to reconnect; if it is slow, wait 2 minutes.
- **The gamepad occasionally stutters when the hotspot and Bluetooth are used together**: the hotspot, Bluetooth and motors are all on 2.4 GHz; under strong interference, increase the distance or move to another location. This is a real-hardware environment issue, not a configuration error.
- **The hotspot is up but the page will not open**: make sure the phone is connected to `Microduck-xxxx` and the address is `https://10.42.0.1:8000/m` (the port `8000` cannot be omitted).

## 4. Related commands (on the board; add sudo for the radxa user)

```sh
sudo microduck-firstboot --tls-only              # Only generate / migrate the HTTPS certificates
sudo microduck-firstboot --tls-only --force      # Force a rebuild (old certificates are backed up automatically)
sudo systemctl restart microduck-studio          # Make Studio reload the certificates
openssl x509 -in /etc/microduck/tls/duck.crt -noout -subject -ext subjectAltName
openssl verify -CAfile /etc/microduck/tls/ca.crt /etc/microduck/tls/duck.crt
```

The server certificate's SAN covers: `duck-xxxx`, `duck-xxxx.local`, `localhost`, `10.42.0.1`, `127.0.0.1`.
