## Choices and boundaries

Use explicit "坐下／站起" (Sit down / Stand up) target steps, and read the main program's real-time state to decide whether a switch is needed and when to continue. Recording the sit_toggle button directly could execute in reverse depending on the starting posture; playing back purely by delay cannot recognize that rise is still executing; neither is adopted. This round does not add kicks, rolls, pick-up, torque off/on or model switching.

The entry is still the existing action recording area. The user first stands steadily and starts walking, then records "坐下→等待→站起→等待" (Sit down → Wait → Stand up → Wait), finishes, names and saves it, and selects it for playback. Both the web D-pad down and the remote sit/stand button, which go through the same path, can be recorded; what is recorded is the target that passed the actual checks and was accepted by robotd. Recording does not end because of a controlled sit/stand, and the empty-action prompt must not report valid sit/stand as empty. A single-play recording ending in a sitting state may be kept; multiple loops require the final state to return to standing, otherwise it is explained that standing must be recorded at the end before looping. A stand-up action is not added automatically.

Saving uses a versioned whitelist of semantic steps; arbitrary robot.do/init/enable are not written to the file; old v1 command recordings remain readable. New content containing sit/stand uses v2, and the boundary that rolling back to an older version is incompatible with v2 must be stated in the records. The compatibility fingerprint continues to include the actual sitstand model and configuration.

## State evidence and execution

robot.policies.enabled is a startup configuration constant; bus.policy_enabled is the runtime switch. The sit/stand sitting flag becomes true immediately when sitting down starts and false immediately when rising starts; homed is not a rise-complete signal either. The main program's existing robot.state.policy reports sit, rise, walk/stand. Studio's existing subscription provides this policy phase, the sample time and actual/target joint information, without restarting or modifying robotd.

Executing sit/stand requires fresh source state, the policy enabled, torque confirmed, the model present, no physical gamepad conflict, and the existing protections passing. Playback reads the target posture: if the target is already reached it does not switch again; if unclear it aborts and does not retry toggle. Standing up must wait for a fresh non-rise walk/stand phase; sitting down needs consecutive samples with fresh sit/sitting and convergence of actual/target joints, and completion cannot be declared only from a toggle acknowledgement or the sitting flag. Missing phase/position evidence, timeouts or unknown execution results all stop subsequent actions, keeping an explicit reason. Request replies and samples are isolated by session/generation and time, and old samples or late replies cannot revive a session.

Sit/stand steps must not be dropped by merging with late continuous targets; when that step is reached the playback timeline pauses and continues only after completion is confirmed. Waiting produces no subsequent joystick/head/mouth targets, and old frames are not re-sent in the next loop. Model content, abnormal state, physical gamepad, e-stop, page switch, background, focus loss, network loss and heartbeat timeout continue to abort subsequent output, and reconnecting does not resume playback.

An ordinary pause/stop cannot physically cancel a sit/stand already handed to robotd. Pause stops continuous control and freezes the timeline, while the sit/stand is still completed by the main program; resuming requires re-verification. Stopping or leaving the page cancels subsequent steps and explicitly states "当前坐站仍会完成" (The current sit/stand will still complete); it does not falsely claim an immediate physical stop, does not automatically stand back up to HOME, and does not automatically turn torque off. A sit/stand still completing blocks new automated sessions; the e-stop continues to use the existing torque-off channel.
