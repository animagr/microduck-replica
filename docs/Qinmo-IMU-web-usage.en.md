# Qinmo IMU: web selection and mounting orientation verification

**English** · [简体中文](Qinmo-IMU-网页使用.md)

This feature ships in two steps via the `2026.10.28` signed software package: first update the web console / voice, then after reconnecting, on the same software update page, support the duck with torque off and explicitly confirm the optional runtime update. No need to re-flash the SD card; a change in the web console version alone does not prove the runtime supports Qinmo. For the full entry point and the one-time bootstrap for older cards, see the [20261028 update notes](software-update-and-qinmo-guide-20261028.en.md). This release has not yet completed a physical upgrade or standing/walking acceptance checks with a real Qinmo unit, and no new image has been released on that basis.

The existing FT6 and IMU-to-DXL continue to be auto-detected by default. FT6 and our own daughterboard use known identities; generic Dynamixel 2.0 only confirms a compatible layout. Qinmo's documentation provides no verifiable unique vendor identity and no basis for automatic unit detection, so it has to be selected once on the same IMU page. After that, every boot reuses the saved type and there's no need to select it again; "已配置 Qinmo" (Qinmo configured) does not mean the vendor was automatically authenticated.

1. Hold the duck steady with both hands, click "失能（卸力）" (Disable (torque off)) in the web console, and wait for the runtime to confirm it is disabled. A supported state that is still starting up and hasn't entered control can also go through the recovery flow; this doesn't mean the web console knows the real torque is off.
2. On the IMU page, under "总线 IMU 类型" (Bus IMU type), select `Qinmo · Feetech`, click "保存类型并重新连接" (Save type and reconnect), then confirm the duck is held steady.
3. Wait for the page to return to calibration mode, capture and compute the orientation following the usual still and lean-forward steps, then hand it to the runtime to complete the level and head-down verification. Re-selecting clears the confirmation state of the old orientation, and verification cannot be skipped.
4. After verification the selected type is kept. A session that was originally in normal control mode returns to control mode with torque disabled; a session that was part of factory calibration continues with "写进主程序" (Write to runtime) per the first-use checklist.

The page shows "配置类型" (Configured type) and "实际连接" (Actual connection) separately. Qinmo angular velocity uses "原始值 ÷ 16.4 °/s" (raw value ÷ 16.4 °/s); the older bus board uses "原始值 × 0.0175 °/s" (raw value × 0.0175 °/s). When the connection fails you can still view the saved type, cancel the session and restore the original parameters. Cancelling a startup recovery stays in safe calibration mode, where you can re-select and verify; it will not start motion automatically.

After refreshing the page or rebooting, an unfinished session and the backup of the original configuration are still there. Cancelling from normal control mode restores the main / saved configuration, the original calibration and the original mode; on failure the recoverable session is kept. Switching is refused if the servo bus is in use, a software update is running, another calibration session is open, or the control state is active or unknown.

First confirm on the software update page that the matching runtime's actual running identity has been verified; this release uses the matching robotd and helper 0.8.0. The evidence of support is the new `configured_imu_profile` diagnostic field; if it's missing, the page clearly prompts you to update the runtime and won't write an unsupported configuration. The optional runtime update only supports this project's known 20261027 baseline; custom or other builds need maintainer verification. Cards without the old upgrade entry still need a one-time SSH bootstrap; users who already have the entry and are supported can do everything in the web console without editing configuration. This first release only supports Qinmo on the Feetech servo bus, not Qinmo's DXL2 mode; I²C chips keep the existing flow.

For transaction limits and tests, see the [helper installation notes](../software/studio/deploy/INSTALL.en.md) and the [software verification record](superpowers/verification/2026-10-27-qinmo-studio.md).
